# 对话与开发记录（时间线）

> 记录用户提出的需求、对应实现与结果。日期为 2026-11-20 ~ 2026-11-21。
> 涉及文件路径为当时工作区路径，符号链接以仓库 `source/` 为准。

## 阶段一：整合语音盒到 QFun / 插件商店

1. **需求**：把语音盒整合进 QEdge，并补 QQ 聊天小悬浮窗的「配置 + 发送语音」和平板模式。
   - 结果：方案评估后**放弃**，改回 QFun 插件路线。
2. **需求**：网站下载链接与原插件整合，自己的下载入口要置顶。
   - 结果：完成站点下载入口合并与置顶。
3. **需求**：插件作者改成 `nl`；聊天设置里的「下载」开关打开后，自动到插件下载页下载并启动插件。
   - 结果：`LocalPluginInjector.smali` 注入条目作者改为 `nl`；`BuiltinPluginInstaller.smali` + 聊天开关逻辑实现自动安装与启用。
4. **需求**：用 GitHub token 上传站点、补充音乐。
   - 结果：站点推送成功（后续 token 失效，换新 token）。
5. **需求**：语音包/音乐列表不要每次重新拉取；站点给数字，客户端比对一致就跳过。
   - 结果：新增 `version.json`（packs/files/songs）数字比对 + 本地缓存 `cloud_packs.json` 秒开。
6. **需求**：插件改版本，否则没有更新通知。
   - 结果：建立「改插件必须同时改 `info.prop` / `latest.json` / 商店注入版本」的发布约定。
7. **需求**：网站 UI 与插件 UI 保持一致；云端音乐不要下载到本地，直接在线播放。
   - 结果：UI 改为两列卡片网格 + 圆形播放按钮；在线播放尝试后因无声回退为下载播放（见阶段二）。

## 阶段二：音乐盒（酷狗 → 网易云）

8. **需求**：音乐改为酷狗概念版获取音乐包，需要登录 Cookie，参考指定插件。
   - 结果：酷狗搜索可用，但播放地址在未登录/接口限制下取不到（`err 30020`、url 为空），方案不可行。
9. **需求**：音乐盒不能云端获取（播放没声音），只能点发送；希望下载一遍再播。
   - 结果：1.4 改为「带 Cookie/Referer 下载到 `musicbox/` → 本地 MediaPlayer 播放」，恢复有声。
10. **需求**：登录账号也搬过来；一个安装包始终能拿到最新插件。
    - 结果：1.6 做网易云粘贴 Cookie 登录；1.7 做自更新双保险（宿主安装 + 自行解压）+ `update.log`。
11. **需求**：网页登录没反应，换成网易云或 QQ 音乐。
    - 结果：确认宿主内嵌 WebView 登录弹窗不可用，先改为粘贴 Cookie。
12. **需求**：仍显示 1.5 没自动更新到 1.6；每次点下载时请求服务器最新版本，低就更新。
    - 结果：1.7 `forceCheckUpdate` 请求 `plugin/latest.json`，比较版本后下载安装；首页加「点此检查更新」。
13. **需求**：账号登录直接套用参考插件（`/workspace/.uploads/..._main.java`），不许自己写。
    - 结果：1.8 整体移植「会员登录管理」：QQ音乐/网易云双平台、WebView 登录、Cookie 保存（`music_login` 配置）、VIP 校验。
14. **需求**：下载页版本号为什么不自动同步。
    - 原因：商店条目是本地注入的，版本号硬编码在 APK 里；其他插件的版本来自 `qfun.store` 接口。
    - 结果：`LocalPluginInjector.readVersion()` 动态读取：`latest.json` → 本地 `info.prop` → 默认值。
15. **需求**：登录后一直显示退出登录；退出再登录保存后又掉登录。
    - 原因：移植代码每次打开登录页都会联网校验 Cookie，失败即自动清除，形成「登录→校验失败→清除」死循环；QQ vkey 校验依赖 Cookie 里的 uin，取不到必然失败。
    - 结果：1.9 取消自动校验/清除；只有手动「退出登录」才删；提高 Cookie 识别条件。
16. **需求**：云端音乐盒加音乐搜索；登录账号后在那里搜索并播放。
    - 结果：1.9.1 搜索带登录 Cookie；播放优先用账号接口 `enhance/player/url/v1`（exhigh），失败回退 outer url。
17. **反馈**：「这也没有搜索啊」（附截图）。
    - 原因：`addNeSearchRow` 用了 `new EditText(...)` 但没有 `import android.widget.EditText`，BeanShell 抛异常，导致搜索框及其后内容全部没渲染。
    - 结果：1.9.2 补 import，搜索框、提示、列表恢复正常。
18. **需求**：播放上一首时搜索并点新歌，旧歌不会停止。
    - 原因：点击判定用列表下标 `idx == gMIndex`，搜索后新列表下标与旧歌相同（如都为 0），被误判为「暂停/继续当前歌」。
    - 结果：1.9.3 改用歌曲 id 判断；搜索刷新后按 id 重新定位播放项；切歌前 `stopMusic()` 释放旧播放器。
19. **需求**：一键删除音乐缓存（已下载的 mp3）。
    - 结果：1.9.4 音乐盒新增「音乐缓存 X MB · 点此一键清除」，确认后删除 `plugin/musicbox/` 下所有文件并停止播放。
20. **需求**：总结全部对话，把聊天/项目资料上传仓库，并单独给一份仓库列表方便交给其他 AI。
    - 结果：新增 `docs/`（项目总览、本开发记录、AI 交接清单），并上传插件源码与 APK 侧关键 smali 到 `source/`。

## 关键经验

- 纯流式播放（MediaPlayer 直接拉网易云/酷狗 URL）会无声：必须带 Cookie/Referer 下载后再播。
- 登录校验不可靠，不能因一次联网校验失败就清除用户 Cookie。
- 插件脚本运行在 BeanShell，未 import 的类会在运行时报错并中断整个 UI 渲染，且不会明显报错。
- 列表下标不可作为「当前播放」的稳定标识，搜索/刷新后必须改用歌曲 id。
- 插件发布必须同时更新：`info.prop`、`plugin/latest.json`、商店注入回退版本，否则更新链路断。
